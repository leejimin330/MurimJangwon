# 무림장원 — 1단계: 세계·인물 코어 설계

작성일: 2026-10-25
상태: 사용자 검토 대기

## 0. 게임 전체 비전

무협 세계에서 작은 문파(또는 세가)를 이끌며 대를 이어 가는 **이야기 생성 시뮬레이션**.
림월드·좀보이드처럼 인물의 특성·관계·사건이 부딪혀 이야기가 저절로 생기고,
크루세이더 킹즈처럼 혼인·후계·외교로 세력을 넓힌다. 플레이어는 정파·사파·마도 중
어떤 길이든 걸을 수 있다 (사파가 되어 정파를 쓸어버리는 플레이 포함).

### 확정된 큰 결정

| 항목 | 결정 |
|---|---|
| 엔진 | Unity 6 (6000.3.23f1), 2D |
| 시점 | 중원 지도(크킹식) + 장원 탑다운 화면(림월드식) 하이브리드 |
| 시간 | 월 단위 턴. 장원 화면·습격전은 실시간 + 일시정지 |
| 전투 | 림월드식 실시간 + 일시정지, 조작은 가볍게 (위치·대상 지정만) |
| 무력 체계 | 경지 단계제 (삼류 → 이류 → 일류 → 절정 → 초절정 → 화경 → 현경) |
| 문파 이름 | 실존 문파명 사용, 데이터 파일로 분리해 교체 가능하게 |
| 범위 | 개인 프로젝트 기준 |

### 개발 단계

| 단계 | 내용 |
|---|---|
| **1. 세계·인물 코어 (이 문서)** | 중원 지도, 문파·세가, 인물, 관계, 혼인·후계, 시간 흐름, 저장 |
| 2. 스토리텔러·이벤트 | 림월드식 이벤트 연출기, 특성 반응 이벤트, 원한·은혜 서사 |
| 3. 무공·경지 | 경지 돌파, 스킬카드, 깨달음·주화입마·폐관수련 |
| 4. 장원 건설 | 탑다운 격자 건설, 제자 생활 |
| 5. 습격전 | 실시간 + 일시정지 전투, 경지 차이 반영 |
| 6. 대형 이벤트 | 정사대전, 혈교·마교 발호, 몽골 침공 (지도 위 자동 계산) |

각 단계는 별도의 설계 → 계획 → 구현 사이클을 거친다.

## 1. 1단계 목표

1단계가 끝나면 플레이어는:
- 시작 지역과 작은 문파/세가를 골라 게임을 시작하고
- 중원 지도에서 지역별 문파와 영향력을 보고
- 인물의 능력치·특성·관계를 확인하고
- 혼담·동맹·선물·모욕 같은 외교와 제자 인사를 하고
- "다음 달"을 눌러 세계가 흘러가며 인물이 늙고, 혼인하고, 아이를 낳고, 죽고, 후계가 이어지는 것을 보고
- 연대기에서 일어난 일을 읽고
- 저장·불러오기를 할 수 있다.

**1단계에 포함하지 않는 것**: 이벤트 시스템(2단계), 무공 카드와 경지 돌파(3단계),
장원 화면(4단계), 전투(5단계), 대형 이벤트(6단계). 1단계의 경지는 숫자 필드로만 존재한다.

## 2. 아키텍처

### 2.1 계층 분리

```
MurimJangwon/
  Assets/
    Murim.Core/        ← 순수 C#. UnityEngine 참조 금지 (asmdef: noEngineReferences = true)
      World/           지역, 문파, 세계 상태
      Characters/      인물, 특성, 관계
      Simulation/      턴 진행, AI, 혼인·출생·사망·후계
      Actions/         플레이어·AI 행동
      Persistence/     저장·불러오기
      Random/          시드 기반 난수
    Murim.Data/        ← JSON 데이터 (StreamingAssets/Data)
    Murim.View/        ← Unity UI. Core를 읽고 행동을 Core에 전달만 함
    Tests/
      Murim.Core.Tests/  EditMode 테스트
```

- **Core는 Unity 없이 돌아간다.** 화면 없이 수백 년 시뮬레이션을 돌려 테스트할 수 있어야 한다.
- **View는 Core 상태를 직접 수정하지 않는다.** 모든 변경은 `IGameAction`을 통해서만 일어난다.
- **결정론**: 같은 시드 + 같은 행동 순서 = 같은 결과. 모든 난수는 `GameRandom`(시드 기반) 하나에서 나온다.

### 2.2 데이터 주도

다음은 코드가 아니라 JSON으로 정의한다:
- `regions.json`: 지역 목록, 인접 관계, 지도 좌표
- `factions.json`: 시작 문파·세가, 소속 지역, 성향, 초기 영향력
- `traits.json`: 특성 정의 (이름, 설명, 능력치 보정, 다른 특성과의 상성, 행동 가중치)
- `names.json`: 성씨·이름 목록 (인물 생성용)

특성의 *행동 효과*(예: 다혈질은 모욕받으면 결투 확률 상승)는 수치 가중치로 JSON에 두고,
그 가중치를 읽는 로직만 코드에 둔다.

### 2.3 라이브러리

- JSON: `com.unity.nuget.newtonsoft-json` (Unity 공식 패키지)
- 테스트: Unity Test Framework (EditMode)
- UI: uGUI (UI Toolkit보다 2D 지도·초상화 배치가 단순함)

## 3. 세계 구조

### 3.1 지역

13개 지역으로 시작한다:
하북, 산동, 하남, 산서, 섬서, 감숙, 사천, 호북, 호남, 강남, 복건, 운남, 요동

각 지역 필드:
- `id`, `name`, `neighbors[]`, `mapPosition`
- `stability` (치안·민심, 0~100, 시작값 50~70)
- 지역 안 문파별 `influence` (0~100). 한 지역 안 모든 문파 영향력 합은 100을 넘지 않는다. 남는 몫은 "무소속"

인접 지역끼리만 직접 외교 외 충돌 행동(5·6단계)이 가능하다. 외교는 거리 제한이 없다.

### 3.2 세력

- `FactionType`: `Sect`(문파) / `Clan`(세가)
- `Alignment`: `Righteous`(정) / `Unorthodox`(사) / `Demonic`(마)
- `chivalry`(협의 점수, -100 ~ +100): 행동에 따라 변한다. 시작값은 정파 +50, 사파 −50, 마도 −80.
  -30 ~ +30 구간에서는 현재 성향을 유지한다 (전환이 오락가락하지 않도록).
  - 정파가 -30 아래로 떨어지면 다음 달 처리에서 사파로 전환, 연대기에 기록
  - 사파가 +30 위로 올라가면 정파로 전환
  - 마도로의 전환과 마도에서의 전환은 1단계에서는 일어나지 않는다 (2단계 이벤트로 처리)
- 세가는 혼인 수락 판정에 +15 보정을 받는다.
- 각 세력 필드: `id`, `name`, `type`, `alignment`, `chivalry`, `homeRegion`, `leaderId`, `heirId`,
  `memberIds[]`, `unnamedDisciples`(이름 없는 제자 수), `silver`(은자), `fame`(명성)

### 3.3 시작 세력

지역마다 3~6개, 전체 약 55개. 대문파(소림·무당·화산·아미·곤륜·점창·청성·종남·개방 등),
오대세가(남궁·모용·제갈·당가·하북팽가), 중소문파, 사파(녹림·장강수로채·흑도 방회),
마도(혈교·천마신교 계열, 변방 지역에 1~2개) 를 섞는다.

### 3.4 플레이어 시작

1. 시작 지역을 고른다.
2. 문파 또는 세가를 고르고 이름과 성향(정·사·마)을 정한다.
3. 장문인(가주) 1명 + 가족 1~3명 + 이름 있는 제자 4명 + 이름 없는 제자 10명, 은자 500, 명성 10, 그 지역 영향력 5로 시작한다.
4. 시작 시드는 무작위이며 설정 화면에서 직접 입력할 수 있다.

## 4. 인물

### 4.1 필드

- `id`, `familyName`, `givenName`, `sex`, `birthMonth`(절대 월 번호), `deathMonth?`
- `factionId`, `role`: `Leader` / `Heir` / `Elder` / `Disciple` / `Family`
- `fatherId?`, `motherId?`, `spouseId?`, `childIds[]`
- `realm`: 0(삼류) ~ 6(현경). 1단계에서는 생성 시 정해지고 나이에 따라 천천히 오르는 단순 규칙만 적용 (3단계에서 교체)
- 능력치 4개 (각 1~20): `constitution`(근골), `insight`(오성), `cunning`(심계), `charisma`(매력)
- `traitIds[]`: 2~4개
- `memories[]`: 원한·은혜 기록 (아래 4.4)

### 4.2 수명과 사망

- 매달 사망 확률 = 나이별 기본 확률 × 경지 보정
- 기본 수명 기준 약 60세, 경지 한 단계당 기대 수명 +8년 (현경은 약 108세)
- 1단계 사망 원인: 노환, 병사(병약 특성이면 확률 상승), 사고 (낮은 확률)
- 사망하면 연대기에 기록, 관계와 기억은 남는다.

### 4.3 특성

1단계 특성 약 20개. 예:
- 성격: 호탕, 음험, 다혈질, 겁쟁이, 탐욕, 의협심, 오만, 온후, 색욕, 충직, 야심
- 체질: 천골지체, 병약, 음한체질, 장수
- 서로 배타적인 쌍이 있다 (호탕↔음험, 겁쟁이↔다혈질, 의협심↔탐욕 일부 등). JSON에 `opposites`로 정의.
- 특성은 다음에 영향을 준다:
  - 능력치 보정
  - 호감도 변화 (같은 특성끼리 +, 반대 특성끼리 −)
  - AI 행동 가중치 (4.6, 5.3)
  - 협의 점수 변화 (의협심은 매년 +, 탐욕은 매년 −)
- 자식은 부모 특성 중 하나를 40% 확률로 물려받는다.

### 4.4 관계와 기억

- 인물 쌍마다 `opinion`(-100 ~ +100). 호감도는 저장 공간을 아끼기 위해 기본값(0 + 특성 상성)과 다른 쌍만 저장한다.
- 관계 태그: `Master`/`Disciple`(사제), `Lover`, `Spouse`, `Rival`, `Nemesis`(원수), `Benefactor`(은인), `SwornSibling`(의형제)
- **기억 (Memory)**: `{ kind: Grudge | Debt, targetId, reason, month, strength }`
  - 1단계에서 기억이 생기는 경우: 모욕당함, 혼담 거절당함, 선물 받음, 파문당함, 후계자 지정에서 탈락함
  - **대물림**: 인물이 죽으면 자식은 부모의 기억 중 강도 50 이상인 것을 강도 절반으로 물려받는다.
  - 기억은 호감도에 계속 반영된다 (원한 = −, 은혜 = +). 강도는 매년 10% 감소, 10 미만이면 사라짐.

### 4.5 혼인과 출생

- 혼인은 서로 다른 세력의 미혼 성인(16세 이상) 사이에서만 제안할 수 있다. 같은 세력 내 혼인은 장문인이 허락하는 행동으로 가능.
- 혼담 수락 판정 (상대 세력 장문인 AI):
  `점수 = 두 장문인 사이 호감도 + (제안 측 명성 − 상대 명성)/10 + 성향 일치 보너스(같으면 +20, 정↔사·마 −40) + 세가 보정 + 특성 보정`
  점수 > 0 이면 수락. 거절되면 제안 측 장문인에게 "혼담 거절" 원한 기억(강도 30).
- 혼인 효과: 두 세력 장문인 호감도 +20, 두 세력 사이 `allianceScore` +15. 배우자는 한쪽 세력으로 이적 (제안 시 선택).
- 출생: 혼인한 부부는 아내 16~45세 동안 매달 약 1.5% 확률로 자식. 자식은 부모 능력치 평균 ± 무작위 4.

### 4.6 후계

- 장문인이 지정한 `heirId`가 있으면 그가 이어받는다.
- 없으면: 문파는 이름 있는 제자 중 (경지 × 3 + 심계 + 매력) 최고점, 세가는 장문인 자식 중 최연장자.
- 계승 시 다른 이름 있는 멤버들은 새 장문인에 대한 호감도로 판정:
  - 호감도 −50 이하이고 야심 특성이면 25% 확률로 **이탈** (다른 세력으로 가거나 독립 — 1단계에서는 무소속 인물로만 처리)
- 플레이어의 장문인이 죽으면 플레이어는 후계자로 이어서 플레이한다.
- **게임 오버**: 플레이어 세력에 이어받을 수 있는 인물이 없을 때.

## 5. 시간 흐름과 행동

### 5.1 월 처리 순서

"다음 달"을 누르면 `TurnProcessor`가 다음 순서로 처리한다:

1. 플레이어가 이번 달 예약한 행동 실행
2. AI 세력 행동 결정·실행 (세력 id 순서, 결정론 유지)
3. 출생
4. 사망
5. 후계 처리
6. 연간 처리 (매년 1월): 나이 증가 반영, 기억 감쇠, 특성에 따른 협의 점수 변화, 경지 단순 상승 판정
7. 성향 전환 판정
8. 세력 수입: 은자 += 지역 영향력 × 2 + 이름 없는 제자 수 × 1, 명성은 영향력 합에 따라 천천히 변화
9. 연대기 기록 확정, 월 번호 +1

### 5.2 플레이어 행동 (1단계)

모든 행동은 `IGameAction`을 구현하고 `CanExecute(world)`, `Execute(world, rng)`를 가진다.

| 행동 | 비용 | 효과 |
|---|---|---|
| 혼담 제안 | 은자 50 | 4.5 판정 |
| 동맹 제안 | 명성 5 | 두 세력 `allianceScore` ≥ 30 이면 동맹 체결 |
| 선물 보내기 | 은자 30~200 | 상대 장문인 호감도 + (은자/10), 은혜 기억 |
| 모욕하기 | 없음 | 상대 장문인 호감도 −30, 원한 기억(강도 40), 사파일 경우 명성 +2 |
| 제자 받아들이기 | 은자 20 | 이름 있는 제자 1명 생성 (매력이 높을수록 능력치 좋은 후보) |
| 이름 없는 제자 모집 | 은자 5/명 | `unnamedDisciples` 증가, 지역 영향력이 상한 |
| 파문 | 명성 −3 | 대상 인물 무소속, 대상에게 원한 기억 |
| 후계자 지정 | 없음 | `heirId` 설정, 탈락한 후보들 호감도 −10 |
| 영향력 확장 | 은자 100 | 지역 영향력 +3 ~ +8 (심계에 비례). 같은 지역 경쟁 세력 장문인 호감도 −5 |
| 의뢰 수행 | 없음 | 은자 +30~80, 정파면 협의 +2, 사파식 "약탈"을 고르면 은자 2배·협의 −5·지역 치안 −5 |

한 달에 할 수 있는 행동 수 = 2 + (장문인 심계 / 8), 소수점 버림.

### 5.3 AI 세력

규칙 기반. 매달 각 AI 세력은 후보 행동마다 점수를 매기고 가장 높은 1~2개를 실행한다.
점수 = 기본 가치 + 장문인 특성 가중치 + 상황 보정 + 작은 무작위.
예: 탐욕 + 사파 → 약탈·약한 이웃 모욕 가중치 상승. 의협심 + 정파 → 같은 지역 사파 견제(모욕·영향력 확장) 상승.

### 5.4 연대기

- `ChronicleEntry { month, text, involvedIds[], importance }`
- 1단계에서 기록하는 일: 출생, 사망, 혼인, 혼담 거절, 동맹, 후계, 이탈, 성향 전환, 파문
- 문장은 템플릿 + 인물 이름으로 생성 (예: "{year}년 {month}월, 무당파 장문인 {name}이(가) 노환으로 세상을 떠났다.")

## 6. 화면 (Murim.View)

1단계 화면은 기능 중심, 그림은 임시.

- **시작 화면**: 새 게임 (지역·세력 선택), 불러오기
- **지도 화면**: 13개 지역을 클릭할 수 있는 2D 지도. 지역 색은 영향력 1위 세력의 성향 색. 클릭 시 오른쪽 패널에 그 지역 문파 목록·영향력 막대
- **세력 패널**: 장문인, 후계자, 멤버 목록, 은자·명성, 성향·협의 점수, 이 세력에 할 수 있는 행동 버튼
- **인물 패널**: 임시 초상화(성별·나이대별 실루엣), 능력치, 경지, 특성, 관계 목록, 기억 목록
- **가계도**: 선택한 인물 기준 3대 (부모·본인·자식)
- **연대기**: 스크롤 목록, 플레이어 세력 관련만 보기 필터
- **상단 바**: 현재 연월, 은자, 명성, 남은 행동 수, "다음 달" 버튼
- **저장·불러오기**: 슬롯 3개 + 매년 자동 저장

## 7. 저장

- 세계 상태 전체(`WorldState`)와 난수 상태를 JSON 하나로 직렬화해 `Application.persistentDataPath/saves/`에 저장
- 저장 파일에 `saveVersion` 필드. 버전이 다르면 불러오기 거부하고 안내 (마이그레이션은 필요해질 때 추가)
- 정적 데이터(지역·특성 정의)는 저장하지 않고 id로만 참조

## 8. 오류 처리

- JSON 데이터 로드 실패: 어떤 파일의 어떤 항목이 문제인지 에러 화면에 표시하고 게임 시작을 막는다
- 데이터 검증: 시작 시 지역 인접 관계 대칭 여부, 존재하지 않는 id 참조, 지역 영향력 합 100 초과를 검사
- 행동 실행 실패(`CanExecute` false): 버튼 비활성화 + 사유 툴팁. Core에서 예외를 던지지 않는다
- 저장 실패: 화면에 알림, 기존 저장 파일은 덮어쓰기 전에 `.bak`으로 보관

## 9. 테스트

EditMode 테스트 (`Murim.Core.Tests`), Unity 에디터 없이 Core 로직만 검증:

- **단위 테스트**: 혼담 판정 공식, 후계 규칙, 기억 대물림·감쇠, 성향 전환, 행동 비용·`CanExecute`, 출생 시 특성 상속
- **결정론 테스트**: 같은 시드로 50년을 두 번 돌려 결과 `WorldState` 직렬화 문자열이 같아야 함
- **장기 시뮬레이션 테스트**: 화면 없이 200년을 돌려
  - 예외 없이 끝나야 함
  - 전체 인물 수가 폭주하거나 멸종하지 않아야 함 (살아 있는 이름 있는 인물 200~1500명 범위)
  - 세력이 전부 사라지지 않아야 함
  - 혼인·후계·성향 전환이 각각 최소 1회 이상 일어나야 함
- **저장 왕복 테스트**: 저장 → 불러오기 → 다시 저장 결과가 같아야 함
- **데이터 검증 테스트**: 배포용 JSON이 8절 검증을 통과해야 함

화면(View)은 수동 확인: 새 게임 → 10년 진행 → 저장 → 불러오기 → 연대기 확인.

## 10. 2단계 이후를 위한 연결점

1단계에서 미리 열어 두는 것 (구현은 하지 않음):
- `ChronicleEntry`와 `Memory`는 2단계 이벤트 시스템이 그대로 쓴다
- `TurnProcessor`는 단계 목록(`ITurnPhase[]`)으로 구성해 2단계 이벤트, 3단계 수련 단계를 끼워 넣을 수 있게 한다
- `realm`은 3단계에서 경지 돌파 시스템으로 교체된다
- 세력 `silver`·`fame` 외 자원은 4단계에서 추가한다
