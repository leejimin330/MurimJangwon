# 무림장원 — 2단계: 이야기꾼·사건 설계

작성일: 2026-10-26
상태: 사용자 검토 대기
선행: [1단계 설계](2026-10-25-murim-stage1-world-character-core-design.md) (구현·검증 완료, 커밋 f87608d)

## 1. 목표

1단계 세계는 숫자가 바뀌며 흘러갈 뿐이다. 2단계에서는 **사건이 일어나고, 사건이 원한·은혜로 남고,
그 원한·은혜가 다음 사건을 부르는** 고리를 만든다.

2단계가 끝나면 플레이어는:
- 새 게임에서 이야기꾼(평온·균형·파란만장)을 고르고
- "다음 달"을 누른 뒤 자기에게 닥친 사건을 선택 창으로 받아 선택지를 고르며 (특성이 있어야 열리는 선택지 포함)
- 다른 인물·세력에게 일어난 사건을 연대기에서 읽고
- 모욕·파문·거절로 생긴 원한이 몇 달·몇 년 뒤 결투·암습·복수로 돌아오고, 은혜가 보은으로 돌아오는 것을 보고
- 부모 대의 원한이 자식 대에 "원수의 자식" 이야기로 이어지는 것을 보고
- 세력이 사건을 통해 마도로 빠지거나 마도에서 벗어나는 것을 볼 수 있다.

**포함하지 않는 것**
- 무공·경지 돌파, 주화입마, 폐관수련은 3단계다. 사건은 경지를 바꾸지 않는다.
- 실제 전투는 5단계다. 결투는 1단계 비무 공식에 사망 확률을 붙여 즉시 계산한다.
- 대형 사건(정사대전·마교 발호·몽골)은 6단계다.

**함께 고치는 1단계 문제**: AI가 같은 상대를 반복해서 모욕한다 (10년 동안 녹림총채가 플레이어를 5번 이상 모욕). 7절에서 다룬다.

## 2. 아키텍처

### 2.1 위치

```
Assets/Murim.Core/
  Events/
    EventDef.cs          사건·역할·선택지·조건·효과 정의 (JSON에서 읽음)
    EventLoader.cs       events.json 읽기 + 검증
    RoleBinder.cs        역할에 인물·세력을 채움
    Conditions.cs        조건 판정
    Effects.cs           효과 실행
    EventText.cs         본문 템플릿 → 문장 (이름·조사 치환)
    EventAI.cs           AI의 선택지 고르기
    Storyteller.cs       긴장도, 플레이어 사건 고르기
    EventPhase.cs        ITurnPhase: 후속 사건 → 세계 사건 → 플레이어 사건
  World/
    EventState.cs        저장되는 사건 상태 (대기·예약·쿨다운·긴장도)
Assets/StreamingAssets/Data/
  events.json
  storytellers.json
Assets/Murim.View/UI/Panels/
  EventDialog.cs         선택 창
```

1단계 원칙을 그대로 따른다.
- Core는 UnityEngine을 쓰지 않는다.
- 난수는 `GameRandom` 하나에서만 나온다.
- 모든 반복은 Ordinal 정렬 순서로 한다.
- Core는 예외를 던지지 않고, 실패하면 `ActionCheck.Fail`을 돌려준다.

### 2.2 월 처리 순서 (변경)

```
플레이어 행동 → AI 세력 → 무소속 인물 → [사건] → 출생 → 사망 → 후계 → 연간 → 성향 → 수입
```

사건 단계(`EventPhase`)는 행동 직후에 온다. 같은 달의 모욕이 같은 달 출생·사망보다 먼저 반영되게 하려는 것이다.
사건 단계는 다음 순서로 진행한다.

1. **예약된 후속 사건**: 이번 달이 된 것을 실행한다.
2. **세계 사건**: 플레이어가 결정자가 아닌 사건을 실행한다.
3. **플레이어 사건**: 이야기꾼이 고른다.

플레이어가 결정자인 사건은 바로 실행하지 않고 `PendingEvents`에 넣는다.
월이 넘어간 뒤 화면이 선택 창을 띄우고, 선택한 결과는 그 자리에서 새 달의 세계에 적용된다.

### 2.3 세션 API (추가)

```csharp
IReadOnlyList<PendingEvent> GameSession.PendingEvents
ActionCheck GameSession.CanChoose(int pendingIndex, int choiceIndex)   // 비활성 사유
ActionCheck GameSession.Choose(int pendingIndex, int choiceIndex)      // 효과 적용, 대기 목록에서 제거
bool GameSession.CanEndTurn                                            // 대기 사건이 있으면 false
```

- 대기 사건이 남아 있으면 `EndTurn`은 아무것도 하지 않고, 화면의 "다음 달" 단추는 비활성("먼저 사건에 답해야 합니다")이다.
- 행동 예약은 대기 사건과 상관없이 할 수 있다.
- 테스트·에디터용으로 `GameSession.ForceEvent(eventId, bindings)`를 둔다. 게임 화면에는 노출하지 않는다.

## 3. 사건 데이터 (`events.json`)

### 3.1 형식

```json
{
  "id": "grudge_duel_challenge",
  "name": "생사결 신청",
  "category": "grudge",
  "weight": 10,
  "tension": 25,
  "cooldownMonths": 36,
  "decider": "target",
  "roles": {
    "avenger": { "pick": "grudgeHolder", "memory": { "kind": "Grudge", "minStrength": 60 }, "ageMin": 16 },
    "target":  { "pick": "memoryTarget", "of": "avenger", "alive": true, "ageMin": 16 }
  },
  "text": "{avenger.title} {avenger:이} 지난날의 원한을 갚겠다며 {target}에게 생사결을 청해 왔다.",
  "choices": [
    {
      "text": "칼을 뽑는다",
      "hint": "목숨을 건 결투",
      "ai": 10, "aiTraits": { "hot_tempered": 15, "coward": -20 },
      "effects": [
        { "duel": { "a": "target", "b": "avenger", "deathChance": 0.3,
          "win":  [ { "fame": { "who": "target", "amount": 8 } },
                    { "removeMemory": { "holder": "avenger", "target": "target" } } ],
          "lose": [ { "fame": { "who": "target", "amount": -5 } } ] } }
      ]
    },
    {
      "text": "은자로 달랜다 (200냥)",
      "requires": { "target": { "silverMin": 200 } },
      "ai": 5, "aiTraits": { "gentle": 10, "arrogant": -15 },
      "effects": [ { "silver": { "who": "target", "amount": -200 } },
                   { "weakenMemory": { "holder": "avenger", "target": "target", "amount": 40 } } ]
    },
    {
      "text": "거절하고 몸을 피한다",
      "ai": 3, "aiTraits": { "coward": 20 },
      "effects": [ { "fame": { "who": "target", "amount": -6 } },
                   { "schedule": { "event": "grudge_ambush", "afterMonths": [6, 18], "roles": { "avenger": "avenger", "target": "target" } } } ]
    }
  ],
  "importance": 2
}
```

| 필드 | 뜻 |
|---|---|
| `category` | `trait` / `grudge` / `debt` / `faction` / `region` / `demonic` / `wanderer` / `followup`. 이야기꾼 가중치와 연대기 분류에 쓴다 |
| `weight` | 후보 사이에서 뽑힐 상대 가중치 |
| `tension` | 플레이어에게 보낼 때 드는 긴장도 비용. 위기 20~40, 기회 5~10, 일상 0~5 |
| `cooldownMonths` | 같은 결정자에게 이 사건이 다시 일어나기까지의 최소 개월 |
| `globalCooldownMonths` | (선택) 세계 전체에서 다시 일어나기까지의 최소 개월. 역병·흉년 같은 지역 사건용 |
| `decider` | 선택지를 고르는 역할. 이 역할이 플레이어면 선택 창, 아니면 AI가 고른다 |
| `followupOnly` | true면 무작위로는 일어나지 않고 `schedule` 효과로만 일어난다 |
| `playerOnly` / `worldOnly` | (선택) 결정자를 플레이어로만, 또는 플레이어가 아닌 인물로만 제한 |
| `importance` | 연대기 중요도 0~2. 1 이상이면 플레이어가 결정자가 아니어도 관련될 때 소식 창을 띄운다 (5.3) |

### 3.2 역할 채우기 (`pick`)

결정자 역할부터 채운다. 그 뒤 다른 역할을 정의 순서대로, 이미 채운 역할을 기준으로 채운다.
후보가 여럿이면 무작위로 하나를 고르고, 조건을 만족하는 후보가 없으면 사건은 일어나지 않는다.

| `pick` | 후보 |
|---|---|
| `anyAdult` | 살아 있는 16세 이상 인물 |
| `leader` | 세력 수장 |
| `grudgeHolder` / `debtHolder` | 해당 종류의 기억을 가진 인물 (역할의 `memory` 조건으로 강도 제한) |
| `memoryTarget` (`of`) | `of` 역할이 가진 가장 강한 해당 종류 기억의 대상 |
| `spouse` (`of`) | 배우자 |
| `leaderOf` (`of`) | `of` 역할이 속한 세력의 수장 |
| `sameFaction` (`of`) | 같은 세력의 다른 인물 |
| `sameRegion` (`of`) | 같은 지역에 있는 다른 성인 (`PersonalRules.IsNearbyAdult`와 같은 기준) |
| `rivalLeader` (`of`) | 같은 지역에 본거지가 있는, 정↔사·마로 대립하는 세력의 수장 |
| `demonicNeighborLeader` (`of`) | 본거지 지역이나 인접 지역의 마도 세력 수장 |
| `new` | 사건이 새로 만드는 인물. `spawn: { ageMin, ageMax, sex?, realmMin, realmMax, statBonus, traits? }`. 선택한 효과가 `recruit`나 `keep`을 하지 않으면 사건이 끝난 뒤 세계에 남기지 않는다 |

- 인물이 위치를 가지지 않으면(세력 소속) 위치는 세력 본거지로 본다.
- 사건 문맥에는 결정자의 세력(`decider.faction`)과 지역(`decider.region`)이 자동으로 묶인다. 효과에서는 `"faction": "avenger"`처럼 역할 이름으로 그 인물의 세력을 가리킨다.

**성능**: 세계 사건은 결정자 후보 전체를 훑지 않는다. 결정자 후보 목록에서 최대 24명을 무작위로 뽑아 앞에서부터 조건을 확인한다.
`grudgeHolder` / `debtHolder` 후보 목록은 사건 단계가 시작될 때 한 번 만든다.

### 3.3 조건

역할마다 다음 조건을 모두 만족해야 한다. 선택지의 `requires`도 같은 형식이다.

| 조건 | 뜻 |
|---|---|
| `alive` | 기본 true |
| `ageMin` / `ageMax` | 나이 |
| `sex` | `Male` / `Female` |
| `traitsAll` / `traitsAny` / `traitsNone` | 특성 |
| `roles` | `Leader`, `Heir`, `Elder`, `Disciple`, `Family`, `Guest` 중 허용 목록. `"None"`은 무소속 |
| `alignment` | 소속 세력 성향 목록 (무소속은 협의로 판정: ≥ 0 정, < 0 사) |
| `married` | true / false |
| `realmMin` / `realmMax` | 경지 |
| `silverMin` / `fameMin` | 지갑 기준 (수장이면 세력 금고·명성, 아니면 개인) |
| `chivalryMin` / `chivalryMax` | 수장이면 세력 협의, 아니면 개인 협의 |
| `factionSizeMin` | 세력의 이름 있는 인물 수 |
| `hasFlag` / `notFlag` | 표식 (3.5) |
| `memory` | `{ kind, minStrength?, target?(역할), inherited? }` |
| `opinionOf` | `{ role, min?, max? }`: 이 인물이 `role`에게 갖는 호감도 |
| `regionStabilityMax` / `regionStabilityMin` | 이 인물이 있는 지역의 치안 |
| `chance` | 0~1. 조건을 다 만족해도 이 확률로만 성립 |

### 3.4 효과

효과는 목록 순서대로 실행한다. 역할이 이미 죽었으면 그 역할에 대한 효과는 건너뛴다.

| 효과 | 뜻 |
|---|---|
| `opinion` `{ who, of, amount }` | `who`가 `of`에게 갖는 호감도 변화 |
| `memory` `{ holder, kind, target, reason, strength }` | 기억 추가 (`Opinion.AddMemory`) |
| `weakenMemory` `{ holder, target, amount }` / `removeMemory` `{ holder, target }` | 기억 약화·삭제 |
| `silver` / `fame` / `chivalry` `{ who, amount }` | 지갑 기준 (조건과 같음) |
| `influence` `{ faction, amount }` | 그 세력 본거지 영향력. `Influence` 규칙의 상한을 지킨다 |
| `stability` `{ region, amount }` | `region`은 역할 이름 (그 인물의 지역) |
| `unnamed` `{ faction, amount }` | 이름 없는 제자 수 (0 미만으로 내려가지 않음) |
| `stat` `{ who, stat, amount }` | 근골·오성·심계·매력 (1~20 범위 유지) |
| `kill` `{ who, cause }` | 사망 처리 (1단계 사망 처리와 같은 경로: 연대기, 기억 대물림, 후계) |
| `flag` `{ who, id, months }` / `clearFlag` `{ who, id }` | 표식 |
| `relation` `{ a, b, tag }` | 관계 태그 (양쪽) |
| `setAlignment` `{ faction, alignment }` | 성향 전환 + 협의를 그 성향 시작값으로. 연대기 기록 |
| `recruit` `{ who, faction, role }` | 인물을 세력에 들이기 (새 인물이면 세계에 추가) |
| `leave` `{ who }` | 세력 이탈, 무소속 |
| `move` `{ who, toward? }` | 인접 지역으로 이동 (무소속·떠돌이만) |
| `allianceScore` `{ a, b, amount }` | 두 인물의 세력 사이 동맹 점수 |
| `duel` `{ a, b, deathChance, win[], lose[] }` | 결투. 승패는 `PersonalRules.SparScore(a, b, 난수 −20~20) > 0`. 진 쪽은 `deathChance` 확률로 사망. `win`/`lose`는 `a` 기준 |
| `contest` `{ who, stat, against, win[], lose[] }` | 능력치 대결: `who.stat + d20 > against`. `against`는 숫자 또는 `{ role, stat }` |
| `chance` `{ p, then[], else[] }` | 확률 분기 |
| `schedule` `{ event, afterMonths: [min, max], roles }` | 후속 사건 예약. 예약 시점의 역할 묶음을 넘긴다 |
| `chronicle` `{ text, importance? }` | 결과 문장을 연대기에 추가 |

모든 사건은 선택 결과와 상관없이 본문과 고른 선택지를 합친 연대기 한 줄을 남긴다:
`"{본문} — {선택지 결과 문장}"`. 결과 문장은 선택지의 `result` 필드에 있다(없으면 선택지 `text`를 쓴다).
`duel`·`contest`·`chance`의 각 갈래에는 `chronicle` 효과로 결과를 덧붙인다.

### 3.5 표식 (flag)

인물에 붙는 기간제 상태다. `Character.Flags: SortedDictionary<string, int>`은 표식 id에서 만료 월로 가는 사전이며, 0이면 영구다.
정의는 `events.json` 최상위 `flags` 배열에 둔다: `{ id, name, description, visible }`.
`visible`인 표식은 인물 패널에 특성처럼 칩으로 보인다.

2단계 표식:
- `injured`(부상): 결투 점수 −15
- `sick`(병상)
- `wanted`(수배)
- `scandal`(추문)
- `sworn_revenge`(복수 맹세)
- `demonic_art`(마공 수련): 매년 협의 −5
- `in_love`(연정)
- `recent_event_*`: 사건 내부용, 보이지 않음

만료된 표식은 연간 처리에서 지운다.

### 3.6 본문 템플릿

| 표기 | 결과 |
|---|---|
| `{role}` | 이름 |
| `{role.title}` | `Titles.Full` (예: "무당파 장문인 장삼풍") |
| `{role.faction}` | 세력 이름 (무소속이면 "강호") |
| `{role.region}` | 지역 이름 |
| `{role:이}` `{role:을}` `{role:은}` `{role:와}` `{role:으로}` | 이름 + 알맞은 조사 (`Josa`) |
| `{role.title:이}` 등 | 앞 표기에 조사를 붙인 것 |

알 수 없는 역할이나 표기는 데이터 검증에서 걸러낸다 (8절).

## 4. 이야기꾼 (`storytellers.json`)

플레이어에게 오는 사건의 빈도와 강도를 조절한다. 세계 사건에는 영향을 주지 않는다.

| 이야기꾼 | 긴장도 증가/월 | 상한 | 월 발동 기본 확률 | 위기 사이 최소 간격 |
|---|---|---|---|---|
| 평온 | 2 | 60 | 0.25 | 18개월 |
| 균형 (기본) | 4 | 100 | 0.35 | 10개월 |
| 파란만장 | 6 | 160 | 0.45 | 5개월 |

`긴장도`는 플레이어 쪽에 쌓인 "사건 여력"이다. 매달 사건 단계에서:

1. 긴장도 += 증가량 (상한까지)
2. 기본 확률로 발동을 판정한다. 실패하면 끝.
3. 후보를 고른다. 플레이어를 결정자로 묶을 수 있고, 쿨다운이 지났고, `tension ≤ 현재 긴장도`인 사건이다.
   위기 사건(`tension ≥ 20`)은 마지막 위기에서 최소 간격이 지나야 후보가 된다.
4. 가중치는 `weight × 범주 보정`이다. 범주 보정은 이야기꾼마다 다르다.
   예를 들어 파란만장은 `grudge`·`demonic` ×1.5, 평온은 `trait`·`debt` ×1.5다.
5. 하나를 뽑아 `PendingEvents`에 넣고, 긴장도 −= `tension`.
6. 같은 달에 두 번째 사건은 긴장도가 상한의 70% 이상일 때만 같은 방식으로 한 번 더 판정한다. 한 달 최대 2개다.

후속 사건(`schedule`)은 이야기꾼을 거치지 않고 예약한 달에 반드시 시도한다. 조건이 다시 맞지 않으면 버린다.
대신 그 달 이야기꾼 사건 수에 포함해, 한 달에 플레이어 사건이 3개를 넘지 않게 한다.

이야기꾼은 새 게임 설정 화면에서 고르고 `NewGameOptions.StorytellerId`로 넘긴다. 게임 중에는 바꿀 수 없다.

## 5. 세계 사건과 소식

### 5.1 세계 사건

플레이어와 무관하게 세계에서 일어나는 사건이다. 매달 4번 시도한다.
1. `worldOnly`이거나 `playerOnly`가 아닌 사건 중에서 가중치로 하나를 뽑는다.
2. 결정자 후보 최대 24명을 표본으로 뽑아 역할 묶기를 시도한다. 플레이어는 결정자에서 제외한다.
3. 성립하면 AI가 선택지를 고르고 효과를 즉시 실행한다.

목표 빈도는 세계 전체에서 한 달 평균 1~4건의 사건이 연대기에 남는 것이다.

### 5.2 AI의 선택

`requires`를 만족하는 선택지 각각에 점수를 매기고, 가장 높은 것을 고른다.
- 점수 = `ai` + Σ(결정자 특성의 `aiTraits` 값) + 난수 0~5
- 점수가 같으면 앞의 선택지를 고른다.

### 5.3 소식

플레이어가 결정자가 아니지만 역할에 묶인 사건, 또는 플레이어 세력 인물이 결정자인 사건은 `importance ≥ 1`이면 소식 창으로 보여 준다.
예: 플레이어 세력 장로가 뇌물을 받은 일.
- 소식은 `PendingEvents`에 "확인" 하나만 있는 항목으로 들어간다.
- 효과는 이미 실행된 상태다.
- 소식은 한 달 최대 3개까지만 띄우고, 나머지는 연대기에만 남긴다.

## 6. 사건 목록 (2단계 초판, 41개)

각 사건의 결정자는 괄호 안에 적는다. 수치는 구현 계획에서 확정하고, 밸런스 테스트(9절)로 조정한다.

### 특성 반응 (trait)
1. **모욕에 격분** (다혈질, 최근 1년 안에 모욕 원한) — 결투를 청한다 (`grudge_duel_challenge` 후속 예약) / 참는다 (기억 강도 +10)
2. **뇌물** (탐욕, 장로·수장) — 받는다 (은자 +, 협의 −5, 준 쪽 호감 +) / 거절한다 (협의 +2)
3. **추문** (색욕, 기혼) — 은자로 덮는다 / 내버려 둔다 (`scandal`, 배우자 호감 −30, 배우자 친정 수장 원한)
4. **원수 앞의 겁쟁이** (겁쟁이, 같은 지역에 강한 원수) — 피신한다 (이동 또는 명성 −) / 버틴다 (용기 판정 `contest`)
5. **오만한 언사** (오만, 다른 세력 인물과 같은 지역) — 상대에게 원한 강도 25, 명성 +1
6. **불의를 보다** (의협심, 지역 치안 ≤ 50) — 나선다 (결투 대 새 인물 "악당", 이기면 협의 +5·명성 +3) / 지나친다 (협의 −2)
7. **하극상 모의** (야심 장로, 수장에 대한 호감 ≤ −20) — 결행한다 (`contest` 심계 대결: 이기면 수장 교체, 지면 파문) / 단념한다
8. **수련의 성과** (근면) — 오성 또는 근골 +1
9. **병상에 눕다** (병약 또는 60세 이상) — 의원을 부른다 (은자 −50, 회복) / 운에 맡긴다 (`sick`, 사망 확률 10%)
10. **호탕한 술자리** (호탕) — 은자 −30, 같은 지역 인물 2명 호감 +10
11. **이간계** (음험 수장, 경쟁 세력 둘이 동맹 점수 ≥ 10) — 꾸민다 (두 세력 동맹 점수 −20, 들키면 `contest` 실패 시 양쪽 원한) / 그만둔다
12. **충신의 간언** (충직 장로, 수장 협의 ≤ 0) — 받아들인다 (협의 +5) / 물리친다 (장로 호감 −20)
13. **화해의 중재** (온후, 같은 세력 두 인물 사이 호감 ≤ −30) — 중재한다 (두 인물 원한 약화) / 맡겨 둔다

### 원한 (grudge)
14. **생사결 신청** (피해자, 원한 ≥ 60) — 3.1의 예시
15. **암습** (피해자. 습격자는 원한 ≥ 70이고 음험이거나 `sworn_revenge`. 무작위로도, 14번에서 몸을 피한 뒤의 후속으로도 일어난다) — 맞선다 (결투, 사망 확률 0.4) / 달아난다 (`injured`, 은자 −) / 대가를 치른다 (은자 300, 원한 약화)
16. **악소문** (원한을 가진 쪽이 결정) — 퍼뜨린다 (대상 명성 −5) / 그만둔다
17. **원수의 자식** (대물림된 원한 보유자, 원수의 자식이 성인) — 칼을 겨눈다 (결투) / 원한을 끊는다 (기억 삭제, 협의 +5) / 복수를 맹세한다 (`sworn_revenge`, 강도 +20)
18. **임종의 유언** (65세 이상, 원한 ≥ 50) — 복수를 당부한다 (후계자·자식에게 같은 원한 강도 40) / 원한을 묻는다 (자식에게 대물림 안 됨)
19. **화해의 손길** (원한 대상 쪽이 결정, 상대가 온후이거나 70세 이상) — 받아들인다 (원한 삭제, 호감 +20) / 뿌리친다 (원한 +10)
20. **파문된 자의 앙갚음** (파문 원한 보유자가 경쟁 세력에 들어감) — 옛 세력의 비밀을 판다 (옛 세력 영향력 −2, 새 세력 +1)

### 은혜 (debt)
21. **은혜 갚기** (은혜 ≥ 40) — 은자를 보낸다 (은혜 대상 +100, 기억 삭제) / 사람을 보낸다 (자기 세력 제자 1명이 상대 세력으로)
22. **은인의 위기** (은혜 대상의 은자 < 50) — 돕는다 (은자 −100, 상대에게 은혜 기억) / 외면한다 (상대 원한 강도 20)
23. **의형제** (은혜·호감 ≥ 60인 같은 지역 두 인물) — 의형제를 맺는다 (`SwornSibling`) / 사양한다
24. **연정** (미혼, 같은 지역 이성 호감 ≥ 30) — 마음을 전한다 (`in_love`, `Lover`, 6~12개월 뒤 혼인 후속 사건) / 마음을 접는다

### 세력 (faction)
25. **장로들의 불화** (수장, 두 장로 사이 호감 ≤ −30) — 한쪽 편을 든다 (편들지 않은 쪽 호감 −25) / 중재한다 (`contest` 매력)
26. **제자의 행패** (수장, 지역 치안 ≤ 60) — 엄벌한다 (제자 호감 −20) / 감싼다 (치안 −5, 협의 −3)
27. **기재(奇才)의 방문** (수장) — 받아들인다 (은자 −50, 능력치 좋은 새 제자 `recruit`) / 돌려보낸다
28. **보호비 요구** (정파·약소 수장, 같은 지역 사파가 더 강함) — 낸다 (은자 −100, 사파 호감 +) / 거절한다 (사파 원한, 6~12개월 뒤 습격 후속: 영향력 −3, 제자 −)
29. **무림대회 초청** (매년 4월, 명성 ≥ 20) — 출전한다 (새 강자와 결투, 사망 확률 0, 이기면 명성 +10) / 사양한다
30. **관부의 간섭** (수장, 영향력 ≥ 15) — 뇌물을 쓴다 (은자 −150) / 맞선다 (영향력 −3, 협의 +2)

### 지역 (region, `globalCooldownMonths` 사용)
31. **도적떼 출몰** (지역 치안 ≤ 45인 곳의 세력 수장) — 토벌한다 (이름 없는 제자 −2~5, 명성 +5, 치안 +10) / 방관한다 (치안 −5)
32. **역병** (지역) — 구휼한다 (은자 −200, 협의 +5, 명성 +5) / 문을 닫는다 (그 지역 인물 각자 3% 사망)
33. **흉년** (지역) — 곡식을 푼다 (은자 −100, 치안 +5) / 값을 올린다 (은자 +100, 치안 −10, 협의 −5)

### 마도 (demonic)
34. **마공 비급의 유혹** (사파 수장 또는 협의 ≤ −30 인물, 야심 또는 탐욕) — 익힌다 (`demonic_art`, 근골 +2. 수장이면 세력 마도 전환) / 불태운다 (협의 +5)
35. **혈교의 포섭** (사파 수장, 마도 이웃 세력이 있음) — 합류한다 (세력 마도 전환, 정파 수장들 호감 −20) / 거절한다 (마도 수장 원한 40)
36. **개과천선** (마도 수장, 온후 또는 의협심, 또는 `demonic_art` 없이 협의 ≥ −40) — 마도를 버린다 (사파 전환, 마도 이웃 원한) / 그대로 간다
37. **마두 출몰** (정파 수장, 마도 이웃 세력이 있음) — 토벌대를 보낸다 (결투 대 새 인물 "마두", 사망 확률 0.3) / 관망한다 (치안 −10)

### 떠돌이 (wanderer, 무소속 결정자만)
38. **길 위의 산적** — 싸운다 (결투 대 새 인물, 사망 확률 0.15) / 은자를 내준다 (가진 은자의 절반)
39. **주막의 시비** — 겨룬다 (결투, 사망 확률 0) / 양보한다 (명성 −1)
40. **낯선 노인의 시험** — 돕는다 (70% 은혜·명성 +2, 30% 오성 +1) / 지나친다
41. **현상 수배** (협의 ≤ −30, 최근 2년 안에 청부를 함) — 추격자와 싸운다 (결투) / 지역을 뜬다 (이동)

"최근 청부"는 `PersonalQuest` 청부를 실행할 때 붙는 보이지 않는 표식 `recent_contract`(24개월)로 판정한다.

## 7. 반복 모욕 방지

1단계 `Insult`에 세력 쌍 쿨다운을 추가한다. 플레이어와 AI에 같이 적용한다.
- 같은 세력이 같은 세력을 **24개월 안에** 다시 모욕할 수 없다. `CanExecute`가 "2년 안에 다시 모욕할 수 없습니다"로 실패한다.
- 쿨다운은 `EventState.Cooldowns`에 `"insult|{가해 세력}|{피해 세력}"` 키로 저장한다. 사건 쿨다운과 같은 저장소를 쓴다.
- AI 모욕 후보는 같은 지역 대립 세력 가운데 쿨다운이 지난 곳에서만 고른다.
- 사건의 원한 서사가 그 자리를 대신한다. 모욕 원한은 14·15·16번 사건으로 이어진다.

## 8. 저장과 검증

### 8.1 저장 (saveVersion 2)

`WorldState`에 추가:
```csharp
public EventState Events = new EventState();
// EventState:
//   string StorytellerId; int Tension; int LastCrisisMonth;
//   List<PendingEvent> Pending;         // EventId, Bindings(역할→id), IsNotice, Text(확정된 본문), CreatedMonth
//   List<ScheduledEvent> Scheduled;     // EventId, Month, Bindings
//   SortedDictionary<string, int> Cooldowns;   // "eventId|deciderId", "eventId|*", "insult|a|b" → 다시 가능해지는 월
```
`Character.Flags`, `Memory.Inherited`(대물림 여부)를 추가한다.

- 버전 1 저장은 불러올 때 빈 `EventState`(이야기꾼 "균형")와 빈 표식으로 채워 받아들인다. 버전 2보다 높은 버전은 1단계처럼 거부한다.
- `new`로 만들어진 인물이 대기 사건에 묶여 있으면 그 인물은 `PendingEvent.Spawned`에 함께 저장하고, 선택 뒤 `recruit`되지 않았으면 버린다.
- 쿨다운은 연간 처리에서 만료된 것을 지운다.

### 8.2 데이터 검증 (게임 시작 시, 실패하면 1단계처럼 오류 화면)

- 사건 id 중복, 알 수 없는 조건·효과 키
- 역할 참조: 효과·본문·`requires`·`of`가 정의되지 않은 역할을 가리킴
- 알 수 없는 특성·표식·사건 id (`schedule`)
- 결정자 역할이 존재하지 않음
- 선택지가 하나도 없거나, 모든 선택지에 `requires`가 있음 (항상 고를 수 있는 선택지가 하나는 있어야 한다)
- `followupOnly`인데 어떤 사건도 `schedule`하지 않음
- 이야기꾼 정의의 범주 이름이 사건 범주와 맞지 않음

## 9. 화면

- **선택 창 (`EventDialog`)**
  - "다음 달" 뒤 대기 사건이 있으면 하나씩 띄운다.
  - 화면 구성: 위에 범주 색 띠와 사건 이름, 본문, 묶인 인물 초상화 1~2개(누르면 인물 패널), 선택지 단추.
  - 선택지 단추에는 `hint`를 툴팁으로 단다.
  - `requires`를 만족하지 못한 선택지는 비활성 상태로 사유 툴팁을 단다. 예: "은자 200냥이 필요합니다", "다혈질만 고를 수 있습니다".
  - 특성 때문에 열린 선택지는 단추 앞에 특성 이름을 붙인다. 예: "[다혈질] 칼을 뽑는다".
  - 고르면 결과 문장을 같은 창에 보여 주고, "확인"을 누르면 다음 사건으로 넘어간다.
  - 바깥을 눌러도 닫히지 않는다.
- **상단 바**
  - 대기 사건이 남아 있으면 "다음 달"은 비활성이고 툴팁 "먼저 사건에 답해야 합니다"를 보인다.
  - 옆에 "사건 N" 단추를 두어 창을 다시 연다.
  - 불러온 저장에 대기 사건이 있으면 바로 띄운다.
- **새 게임 설정**: 이야기꾼 선택 (평온 / 균형 / 파란만장, 설명 한 줄씩)
- **인물 패널**: 보이는 표식을 칩으로 보인다 (툴팁: 설명, 남은 개월). 기억에 대물림 여부를 붙인다 ("부친에게서 물려받은 원한").
- **연대기**: 사건 기록은 범주 색 점을 붙인다. 필터에 "사건만"을 추가한다.

## 10. 테스트

Core 테스트 (`dotnet test`와 Unity EditMode 둘 다):

- **데이터**: 배포용 `events.json`·`storytellers.json`이 8.2 검증을 통과한다. 잘못된 예제 데이터마다 정확한 오류 문장을 낸다.
- **조건**: 3.3의 조건마다 참·거짓 사례
- **역할 묶기**: 각 `pick`이 맞는 인물을 고르고, 후보가 없으면 사건이 성립하지 않는다. 같은 시드면 같은 인물을 고른다.
- **효과**: 3.4의 효과마다 결과 확인. `kill`은 기억 대물림과 후계까지 1단계와 같게 이어진다. `duel`의 사망 확률 0과 1 경계.
- **본문**: 조사 표기가 받침 유무에 맞게 바뀐다. 알 수 없는 표기는 검증에서 걸린다.
- **이야기꾼**:
  - 각 시나리오, 각 이야기꾼으로 50년을 돌렸을 때 플레이어가 받은 사건(소식 제외)의 연평균
    평온 1~4, 균형 3~8, 파란만장 6~14
  - 이 세 값이 평온 < 균형 < 파란만장 순서
  - 한 달 3개를 넘는 달이 없다
  - 위기 사건 사이 최소 간격을 지킨다
  - 테스트에서 플레이어 선택은 "AI와 같은 방식"으로 자동 선택한다
- **세계 사건**: 50년 평균 월 1~4건. 200년 장기 시뮬레이션의 1단계 기준(살아 있는 이름 있는 인물 500~4000명, 세력 소멸 없음)을 계속 만족한다.
- **서사 고리**: 200년 시뮬레이션에서
  - 원한 → 생사결·암습 사건이 일어난다
  - 대물림 원한 → "원수의 자식"이 일어난다
  - 은혜 갚기가 일어난다
  - 마도 전환이 1회 이상 일어나고, 마도 세력이 전체 세력의 40%를 넘지 않는다
- **모욕 쿨다운**: 같은 세력 쌍 모욕 사이가 늘 24개월 이상. 10년 시뮬레이션에서 한 세력이 플레이어를 모욕한 횟수 ≤ 5.
- **세션**: 대기 사건이 있으면 `EndTurn`이 진행되지 않는다. `Choose`의 비활성 사유. 대기 사건이 있는 상태에서 저장 → 불러오기 → 같은 선택 → 같은 결과 (결정론).
- **저장**: 버전 1 저장 파일을 불러올 수 있다. 저장 왕복이 같다.

화면은 1단계처럼 `UiScenario.RunTask*`로 확인한다:
- 사건을 강제로 띄운다
- 특성 선택지가 비활성이고 사유 툴팁이 뜬다
- 선택 → 결과 → 다음 사건으로 넘어간다
- 대기 중에는 "다음 달"이 비활성이다
- 저장·불러오기 후 창이 다시 뜬다
- 인물 패널에 표식 칩이 보인다
- 연대기 "사건만" 필터가 동작한다

## 11. 3단계 이후를 위한 연결점

- 결투 효과(`duel`)는 5단계 전투가 생기면 그 결과를 쓰도록 교체한다. 사건 데이터는 그대로 둔다.
- 3단계 무공·경지 사건(깨달음, 주화입마, 비급)은 같은 사건 형식에 `realm`·`technique` 조건·효과를 추가해 넣는다.
- 6단계 대형 사건은 세계 사건 범주 `world_crisis`로 추가하고, 이야기꾼과 별개의 연대표로 움직인다.
